# Тригери та алерти

Збережені тригери в поточному YAML управляються макросами хоста:

- `{$UPS.NODATA}` (типово 25m при polling 10m): відсутність свіжих даних.
- `ups.OnBattery=1`: живлення від батареї (**High** у V10.5).
- `ups.BatteryLow=1`: низький заряд за прапорцем UPS (**Disaster**).
- `{$UPS.INPUT.MIN/MAX}`, `{$UPS.OUTPUT.MIN/MAX}`, `{$UPS.FREQ.MIN/MAX}`, `{$UPS.TEMP.MAX}`, `{$UPS.LOAD.MAX}`: межі фізичних показників.
- `{$UPS.BATTERY.VOLT.WARN/CRIT}`: пороги напруги батарейного блока; `0` вимикає ці пороги до калібрування.
- `{$UPS.SOC.WARN}=30`, `{$UPS.SOC.CRIT}=15`: пороги **лише для справжнього каліброваного SOC**; `{$UPS.SOC.ALERTS.ENABLED}=0` за замовчуванням, тому відсоткові тригери поки не активні.

**Не плутати:** картки dashboard із кольоровим фоном та `thresholds` — це візуальна індикація, а не підтверджена доставка alert. Для email/Telegram потрібні Media/Actions Zabbix і тест подій без відключення критичного UPS.

**Критичне обмеження:** розраховані за напругою `RuntimeEstimated` і `CellVoltageEstimated` не дають достовірного SOC, особливо за змішаних батарей 6S/7S. Не використовувати як єдине джерело рішення про вимикання живлення.
