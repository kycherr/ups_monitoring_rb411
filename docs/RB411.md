# MikroTik RB411: інвентаризація та інтеграція

## Підтверджено CLI з вузла `mt_PWR_*` (історичний знімок, 2026-10-15)

| Поле | Значення |
|---|---|
| RouterBOARD model / board | `411` / `RB411` |
| RouterOS | `6.49.23 (stable)` |
| Architecture | `mipsbe` |
| CPU | `MIPS 24Kc V7.4`, 300 MHz, 1 core |
| RAM | 32.0 MiB, вільно 5.4 MiB на момент перевірки |
| CPU load | 100% на момент перевірки, не доведено як сталий стан |
| Flash | 63.8 MiB total, 43.5 MiB free |
| Firmware type | `ar7100`, current firmware 2.39, upgrade firmware 6.49.23 |
| Packages | `iot`, `ups`, `wireless` та інші встановлені; `ipv6` disabled |
| Expansion | один **miniPCI** (не PCI Express) |

Серійний номер умисно не включено до публікабельного репозиторію. IP `172.16.0.25` — адреса RAW TCP шлюзу UPS Почаєва, не секрет автентифікації.

## Робоча схема

- RB411 перетворює **RS-232 / Megatec** на RAW TCP `172.16.0.25:9999`.
- Налаштування UART, підтверджені проєктом: **2400 baud, 8N1**, Q1 завершується `\r`.
- Скрипт використовує TCP, отримує рядок приблизно `(222.3 120.0 229.8 037 50.0 2.28 20.0 00000001\r`.
- Вхідний Megatec Q1 містить *fault_voltage* `120.0`, це **не кількість комірок**.
- TCP `recv()` може повернути неповну відповідь або фрагмент попередньої UART-сесії. Наявний колектор накопичує буфер до CR/LF, відкидає недійсні фрейми й повторює запит (у межах timeout).

## CLI для діагностики, без змін конфігурації

```routeros
# RB411, admin CLI
/system routerboard print
/system resource print
/system package print
/tool profile duration=20s
/port print detail
/port remote-access print detail
/ip firewall filter print
```

**Не копіювати сліпо `/port remote-access` setup**: конкретне ім'я serial-порту та вже активний remote-access не експортовані, тому конфігурацію для створення TCP bridge не вигадуємо.

## Bluetooth / кілька BMS

- Пакет `iot` встановлений, але це **не підтверджує** BLE апаратне забезпечення.
- Через miniPCI / MIPSBE RouterOS 6.49.23 сумісність BLE не встановлена.
- Для BMS (JK/JBD/Daly — модель наразі невідома) раціонально розглядати **окремий ESP32/Linux BLE gateway**, із послідовним GATT-опитуванням, MQTT/HTTP і моніторингом в Zabbix.
- 100% CPU на момент знімка робить додаткову BLE-навантаження на RB411 ризикованим.

## Безпечні перевірки на сервері `mon`

```bash
# mon, root
nc -vz -w 3 172.16.0.25 9999
sudo -u zabbix python3 /usr/lib/zabbix/externalscripts/ups_megatec.py 172.16.0.25 9999 3
```

Ні `firmware upgrade`, ні reset Serial, ні масове перепідключення UPS як початкові дії не потрібні.
