# Операційна діагностика

## Симптом: Connection refused

Гіпотеза: відмова TCP:9999 або конкуренція клієнтів RAW Serial; не доказ помилки Q1. Мінімальна перевірка:

```bash
# mon, root
nc -vz -w 3 172.16.0.25 9999
sudo -u zabbix /usr/lib/zabbix/externalscripts/ups_megatec.py 172.16.0.25 9999 3
ss -tan '( dst 172.16.0.25 and dport = :9999 )'
```

## Симптом: Invalid Q1 response

Спостерігалися неповні ASCII-фрагменти `(224.9 1`, потім `20.0 229.6 ...` та повний фрейм у третьому тесті. Один `recv()` не дорівнює UART-повідомленню; колектор читає до CR/LF та робить до двох спроб з обмеженням загального timeout. За повторного збою перевірити сирий HEX пасивним Q1-запитом, CPU profile RB411 і конкурентні опитувачі. Не міняти швидкість 2400 8N1 наосліп.

## Зміни без втрати доступу

Не рестартувати RouterOS, не виконувати serial flush або масово перезапускати Zabbix як перший крок. Після імпорту шаблону перевірити 1 тестовий UPS і тільки тоді розповсюджувати шаблон на інші.

## Стан живлення на дашборді

`ups.PowerStateText` показує лише текст, `ups.PowerStateCode` — числову діагностику. Якщо зникають показники, перевіряй master JSON і тригер `nodata`; `НЕВІДОМО` означає отриманий, але нерозпізнаний стан, а не втрату зв’язку.
